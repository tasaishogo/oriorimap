## 1. 概要

各所で作られる主題図（バス停マップ・観光マップ・避難所マップ等）が互いに交わらず孤立している。GISを知らない一般ユーザーが、テーマに沿った地図を簡単に作成・公開でき、複数の地図を自由に重ね合わせ（がっちゃんこ）て新しい気づきを得られるWebサービスを作る。重ね合わせた地図は保存・共有でき、事前登録したサイトへの埋め込み（embed）も可能にする。地図表示はGeolonia Maps（日本向け・利用条件が自由）を採用し、趣味・小規模・低コストで運用する。ソースコードはOSSとして公開する。

MVPで扱う地物は**地点（ポイント）情報のみ**。例えば「バス停マップ×催し物マップ」の重ね合わせは実現できるが、「浸水想定区域（面データ）×避難所」のような面・線データを含む重ね合わせは将来対応（§6）。

**派生コンテンツの基本方針**: 本サービスで「公開」された地図は、他のユーザーによる重ね合わせ・重ね合わせ地図への組み込み・その公開/embedを許諾したものとして扱う（利用規約に明記する。note記事の「がっちゃんこOK前提」の思想に基づく）。組み込まれた元地図のタイトル・作成者は出典として常に表示する（R5.5）。元地図オーナーによる重ね合わせ拒否（オプトアウト）設定は将来検討（§6 Ask first）。

### 用語定義

| 用語 | 定義 |
|---|---|
| 地図（主題図） | 1人のオーナーが作る、テーマを持ったスポットの集合。本サービスの基本単位 |
| スポット | 地図上の1地点。位置・タイトル・説明・アイコン等を持つ（Googleマップの「ピン」に相当） |
| 重ね合わせ（がっちゃんこ） | 複数の公開中の**主題図**を1画面に重ねて表示すること。参照型（元地図の最新内容を常に反映）。重ね合わせ地図を対象にした再帰的な重ね合わせは不可 |
| 重ね合わせ地図 | 重ね合わせの組み合わせ（主題図IDの組）に名前を付けて保存したもの。固有URLを持ち、それ自体も公開・embed可能 |
| embed | 外部サイトへのiframe埋め込み。事前に登録したドメインのみ許可 |
| オーナー | 地図・重ね合わせ地図を作成したユーザー。公開設定・削除・embedドメイン管理の権限を持つ |
| 共同編集者 (P2) | オーナーの招待により地図の内容編集権限（公開設定・削除・招待を除く）を持つユーザー |
| 管理者 | サービス運営者。通報対応（非公開化・削除）の権限を持つ |
| 公開 / 非公開 | 公開: 誰でも閲覧・検索・重ね合わせ・embed発行の対象になる状態。非公開: オーナー（と共同編集者）のみ閲覧できる下書き状態 |
| 許可ドメイン | オーナーがembed先として事前登録したドメイン。登録外のサイトでは埋め込み表示されない |

## 2. ユーザーと利用シナリオ

- 想定ユーザー: GISに詳しくない一般ユーザー（地域情報を発信したい個人・商店・団体、地域活動に関心のある市民）。初期は桐生市周辺で数十人規模、閲覧は月間1万PV程度を想定
- 主要シナリオ:
  1. 地域の商店主が「開業50年以上の老舗マップ」を作成して公開する
  2. 訪問者が「桐生サイクルマップ」と「かるたマップ」を重ね合わせ、サイクリングルート沿いの立ち寄り先を発見する（スマホ・現在地表示を利用）
  3. 地域メディアの運営者が、記事で紹介したスポットの地図を自サイトに埋め込む

## 3. 機能要件

注: 本章の「(仮)」付き数値は暫定値であり、技術設計フェーズで確定して承認ゲート②で最終値として提示する（§9参照）。

### R1: アカウント登録・ログイン・退会

ストーリー: 地図を作りたい人として、簡単にアカウントを作ってログインしたい。なぜなら自分の地図を管理するため。

受け入れ基準:
- R1.1 WHEN 訪問者がメールアドレス・パスワード・表示名で登録した時 THE SYSTEM SHALL 確認メールを送信し、**メール内の確認コード**の検証後にアカウントを有効化する（2026-08-11 改訂: 「メール内リンク」→「確認コード」。決定ログ #31）
- R1.2 WHEN 訪問者がGoogleアカウントでログインした時 THE SYSTEM SHALL 初回はアカウントを自動作成し、以降は同一アカウントとしてログインさせる
- R1.3 THE SYSTEM SHALL パスワードを平文で保存せず、マネージド認証基盤またはソルト付きハッシュで管理する
- R1.4 WHEN パスワード認証を持つユーザーがパスワード再設定を要求した時 THE SYSTEM SHALL 有効期限付きの再設定リンクを登録メールアドレスに送信する
- R1.5 THE SYSTEM SHALL 公開されている地図・重ね合わせ地図の閲覧をログインなしで許可する
- R1.6 IF 未ログインの訪問者が地図の作成・編集・保存操作を要求した場合 THEN THE SYSTEM SHALL 操作を拒否しログイン画面へ誘導する
- R1.7 IF 同一アカウントでログインに5回連続失敗した場合 THEN THE SYSTEM SHALL 当該アカウントのログイン試行を15分間ブロックする (仮)
- R1.8 IF Googleログインのメールアドレスが既存のメール登録アカウント（メール検証済み）と一致した場合 THEN THE SYSTEM SHALL 別アカウントを作成せず同一アカウントに連携してログインさせる
- R1.9 IF パスワード認証を持たないアカウント（Googleログインのみ）でパスワード再設定が要求された場合 THEN THE SYSTEM SHALL 再設定リンクを送信せず、Googleログインの利用を案内する
- R1.10 WHEN ユーザーが退会を要求し確認操作を行った時 THE SYSTEM SHALL アカウントの個人情報および当該ユーザーが作成した地図・重ね合わせ地図・アップロード画像を削除する（当該地図を参照していた他者の重ね合わせ地図はR4.5に従いレイヤー除外として扱う）
- R1.11 IF Googleログインのメールアドレスがメール未検証の既存アカウントと一致した場合 THEN THE SYSTEM SHALL 自動連携を行わず、既存アカウントのメール検証を完了するよう案内する（アカウント乗っ取り防止）

### R2: 地図（主題図）の作成・編集

ストーリー: 地図作成者として、テーマに沿ったスポットとオリジナルアイコンで主題図を作りたい。なぜなら既製の地図では表現できない地域情報を発信するため。

受け入れ基準:
- R2.1 WHEN ログインユーザーが地図を新規作成した時 THE SYSTEM SHALL タイトル（必須）・説明・タグを持つ地図を「非公開（下書き）」状態で保存する
- R2.2 WHEN 作成者が地図上の地点クリックまたは住所・地名検索（ジオコーディング。§5参照）で位置を指定した時 THE SYSTEM SHALL その位置にスポット（タイトル必須、説明・写真1枚・外部リンクは任意）を追加する
- R2.3 THE SYSTEM SHALL スポットのアイコンとして、プリセットアイコンの選択と、ユーザーがアップロードした画像（PNG/JPEG/WebP、1ファイル1MB以内 (仮)）の利用を許可する
- R2.4 WHEN 作成者が地図を「公開」に切り替えた時 THE SYSTEM SHALL 当該地図を検索・一覧・重ね合わせ選択・embed発行の対象にする
- R2.5 WHEN オーナーが地図を削除した時 THE SYSTEM SHALL 確認操作の後に地図を削除し、当該地図を参照する重ね合わせ地図から当該レイヤーを除外する
- R2.6 IF スポットのタイトルが空のまま保存が要求された場合 THEN THE SYSTEM SHALL エラーを表示し保存を拒否する
- R2.7 IF アップロード画像が許可形式・サイズ上限を満たさない場合 THEN THE SYSTEM SHALL 制限値を明示したエラーを表示し受理しない
- R2.8 IF 1つの地図のスポット数が上限1,000件 (仮) を超える場合 THEN THE SYSTEM SHALL 追加を拒否し上限を通知する
- R2.9 IF 住所・地名検索で該当する場所が見つからない場合 THEN THE SYSTEM SHALL 見つからない旨を表示し、地図クリックでの位置指定を案内する
- R2.10 THE SYSTEM SHALL 地図・重ね合わせ地図の表示時に、登録スポット全体が収まる領域を自動算出して初期表示する（スポット0件の場合は日本全体 (仮)）
- R2.11 WHEN 地図・スポットの削除により参照されなくなったアップロード画像が生じた時 THE SYSTEM SHALL 当該画像ファイルを7日以内 (仮) にストレージから削除する

対象データはポイント（地点）のみ。線・面（ルート・エリア）はMVP対象外（§6参照）。

### R3: 地図の検索・一覧

ストーリー: 閲覧者として、興味のあるテーマ・地域の地図を見つけたい。なぜなら知らない地図と出会って重ね合わせを試すため。

受け入れ基準:
- R3.1 WHEN 訪問者がキーワードを入力して検索した時 THE SYSTEM SHALL タイトル・説明・タグに部分一致する公開中の地図・重ね合わせ地図を一覧表示する
- R3.2 THE SYSTEM SHALL 公開中の地図・重ね合わせ地図の一覧を新着順・更新順で表示できるようにする
- R3.3 IF 検索結果が0件の場合 THEN THE SYSTEM SHALL 0件である旨と検索条件の変更を促すメッセージを表示する
- R3.4 (P2) WHEN 訪問者が地域（作成者が地図のメタデータとして設定した都道府県・市区町村タグ）で絞り込んだ時 THE SYSTEM SHALL 当該地域タグを持つ地図に絞り込む

### R4: 複数地図の重ね合わせ表示

ストーリー: 閲覧者として、複数の地図を1画面に重ねて見たい。なぜなら単独の地図では見えない関係（例: バス停×催事会場）に気づくため。

重ね合わせの対象は主題図のみ（用語定義参照。重ね合わせ地図の再帰的な重ね合わせは不可）。

受け入れ基準:
- R4.1 WHEN 閲覧者が閲覧中の地図に他の公開中の主題図を追加選択した時 THE SYSTEM SHALL 選択された全地図のスポットを1つの地図画面上に重ねて表示する
- R4.2 THE SYSTEM SHALL 重ね合わせ表示中に、レイヤー（元地図）ごとの表示/非表示を個別に切り替えられるようにする
- R4.3 THE SYSTEM SHALL 重ね合わせ表示中に、各スポットがどの元地図に属するかを凡例で識別できるようにする
- R4.4 THE SYSTEM SHALL 重ね合わせ表示を常に各元地図の最新の公開内容で描画する（参照型・自動最新化）
- R4.5 IF 重ね合わせ対象の元地図が非公開化または削除された場合 THEN THE SYSTEM SHALL 当該レイヤーを表示から除外し、レイヤーが利用不可となった旨を閲覧者に表示する
- R4.6 IF 重ね合わせ対象が10地図 (仮) を超えて選択された場合 THEN THE SYSTEM SHALL 追加を拒否し上限を通知する
- R4.7 WHEN 閲覧者が現在地表示を要求し、ブラウザの位置情報利用を許可した時 THE SYSTEM SHALL 地図上に現在地を表示する
- R4.8 IF 閲覧者が位置情報の利用を拒否または取得に失敗した場合 THEN THE SYSTEM SHALL 現在地なしの通常表示を継続する

### R5: 重ね合わせ地図の保存・共有

ストーリー: 閲覧者・作成者として、良い組み合わせを見つけたら名前を付けて保存し、URLで人に共有したい。なぜなら発見した組み合わせ自体が価値を持つため。

保存者は元地図のオーナーである必要はない（§1「派生コンテンツの基本方針」参照）。

受け入れ基準:
- R5.1 WHEN ログインユーザーが重ね合わせ状態に名前を付けて保存した時 THE SYSTEM SHALL 参照する主題図IDの組を「重ね合わせ地図」として保存し、固有のURLを発行する
- R5.2 WHEN 訪問者が公開中の重ね合わせ地図のURLを開いた時 THE SYSTEM SHALL ログイン不要で各元地図の最新内容を重ねて表示する
- R5.3 THE SYSTEM SHALL 重ね合わせ地図にも地図と同様の公開/非公開の切り替えを提供する
- R5.4 IF 重ね合わせ地図の参照先すべてが利用不可（非公開化・削除）になった場合 THEN THE SYSTEM SHALL 表示可能なレイヤーがない旨を明示して空の地図を表示する
- R5.5 THE SYSTEM SHALL 重ね合わせ地図の画面に、参照する各元地図のタイトルと作成者名を出典として表示する

### R6: 外部サイト埋め込み（embed）

ストーリー: 地図のオーナーとして、自分の地図（単体・重ね合わせ）を指定したサイトにだけ埋め込めるようにしたい。なぜなら地域メディア等と連携しつつ無断利用を防ぐため。

受け入れ基準:
- R6.1 WHEN 公開中の地図・重ね合わせ地図のオーナーが埋め込み許可ドメインを登録した時 THE SYSTEM SHALL 埋め込み用のiframeコードを発行する
- R6.2 WHEN 登録済みドメイン上のページがembed URLを読み込んだ時 THE SYSTEM SHALL 当該地図を表示する
- R6.3 IF 未登録ドメイン上のページがembed URLをiframeで読み込んだ場合 THEN THE SYSTEM SHALL 地図を表示しない（ブラウザによる埋め込み拒否または代替メッセージの表示）
- R6.4 THE SYSTEM SHALL embed表示を閲覧専用とし、編集系のUI・操作を提供しない
- R6.5 IF 非公開の地図・重ね合わせ地図に対してembedコードの発行が要求された場合 THEN THE SYSTEM SHALL 発行を拒否し、公開が必要である旨を表示する
- R6.6 WHEN オーナーが許可ドメインを削除した時 THE SYSTEM SHALL 以後の当該ドメインからの埋め込み表示を拒否する

### R7: データインポート

ストーリー: 地図作成者として、既存のGoogleマイマップやスプレッドシートの資産を取り込みたい。なぜなら手作業での再入力なしに移行するため。

受け入れ基準:
- R7.1 WHEN 作成者がKML/KMZファイル（Googleマイマップのエクスポート形式）をアップロードした時 THE SYSTEM SHALL ポイント情報（位置・名称・説明）をスポットとして取り込み、取り込み件数とスキップ件数を表示する
- R7.2 WHEN 作成者が所定フォーマット（列: 名称・緯度・経度・説明等）のCSVをアップロードした時 THE SYSTEM SHALL 各行をスポットとして取り込む
- R7.3 THE SYSTEM SHALL KML内のポイント以外の図形（線・面）をスキップし、スキップした旨と件数を報告する
- R7.4 IF ファイルが解析不能、または有効な位置情報を1件も含まない場合 THEN THE SYSTEM SHALL 取り込みを中止し、原因（該当行番号・理由）を含むエラーを表示する
- R7.5 IF 取り込み後のスポット数が地図のスポット上限（R2.8）を超える場合 THEN THE SYSTEM SHALL 取り込みを中止し、上限超過を通知する

### R8: 通報・モデレーション

ストーリー: 運営者として、不適切な公開コンテンツに対処したい。なぜなら公開UGCサービスの安全性を保つため。

受け入れ基準:
- R8.1 WHEN 閲覧者が公開中の地図・スポット・重ね合わせ地図を理由付きで通報した時 THE SYSTEM SHALL 通報内容（対象・理由）を記録し、管理者が一覧で確認できるようにする
- R8.2 WHEN 管理者が通報対象に対処した時 THE SYSTEM SHALL 地図・重ね合わせ地図に対しては非公開化または削除を、スポットに対しては個別削除を実行し、直ちに検索・一覧・重ね合わせ・embedの全てから除外する
- R8.3 IF 同一の閲覧者が1時間に10件 (仮) を超える通報を送信した場合 THEN THE SYSTEM SHALL 以後の通報を一時的に受け付けない

### R9: 共同編集 (P2・第2段階)

ストーリー: 地図のオーナーとして、信頼できる人を招待して一緒に地図を育てたい。なぜなら1人では情報の網羅・更新に限界があるため。

受け入れ基準:
- R9.1 WHERE 共同編集機能が有効な場合 WHEN オーナーが他のユーザーを共同編集者として招待し相手が受諾した時 THE SYSTEM SHALL 当該ユーザーに地図の編集権限（公開設定・削除・招待を除く）を付与する
- R9.2 WHERE 共同編集機能が有効な場合 THE SYSTEM SHALL 編集の保存を後勝ちで適用し、保存の都度、更新履歴（誰が・いつ・何を）を記録する
- R9.3 WHERE 共同編集機能が有効な場合 WHEN オーナーまたは共同編集者が更新履歴から過去版の復元を要求した時 THE SYSTEM SHALL 地図の内容を当該版に戻す
- R9.4 WHERE 共同編集機能が有効な場合 WHEN オーナーが共同編集者を解除した時 THE SYSTEM SHALL 当該ユーザーの編集権限を直ちに無効化する

MVPのデータモデル設計はR9の将来追加を阻害しない形とする（設計書で考慮）。

## 4. 非機能要件

- 性能 (仮): 想定同時アクセス10ユーザー・月間閲覧1万PV。地図閲覧ページの初期表示は Lighthouse（モバイル・Slow 4G設定）のLCPで3秒以内。主要API（地図一覧・検索、地図データ(GeoJSON)取得）はp95 500ms以内（アクセスログ/CloudWatch等で計測）
- 地図表示回数: Geolonia無料枠（20,000回/月）内での運用を基本とし、超過見込み時にProプラン（月4,378円税込）への切替を判断する。表示回数を月次で把握できるようにする
- セキュリティ: 認証はマネージド認証基盤の利用を優先（詳細は設計書）。保持する個人情報はメールアドレス・表示名・パスワード（ハッシュ）のみ。全通信HTTPS。アップロード画像はサーバー側で形式検証（Content-Type偽装対策）。OSS公開のためシークレット類はリポジトリに含めない
- 法務・表記: 全ての地図表示画面（通常・embed含む）に地図の帰属・クレジット表記を常時表示し、非表示にする設定を設けない。~~Geoloniaの表記義務の正式確認は**本番公開前の必須確認事項（リリースゲート）**とする（§9）~~ → **2026-08-11 調査完了によりリリースゲート解除**（§9・決定ログ#29）。実装要件は「MapLibre の `AttributionControl` を無効化しない（`attributionControl: false` を渡さない）」に帰着する
- 可用性・運用: 商用SLAなし（趣味運用・計画外停止は数時間/月まで許容）。データは日次バックアップ・7世代保持 (仮)。復元手順を文書化し、本番公開前に1回復元テストを実施する。死活監視とコスト超過アラート（閾値: 月額目標の80%）を設ける
- コスト: インフラ月額目標 $0〜10（無料枠中心・低いほど良い）。Geolonia Pro移行時を含めた総額上限は月5,000円
- デザイン方針: 印象キーワード「織物・十二単（かさねの色目）・派手すぎない上品な華やかさ」。メインカラー・トーンは技術設計フェーズで**デザイン案・モックを3〜5案提示して選定**する。ライトモードのみ（MVP）。主要利用者層は地域住民（中高年含む）のため基本文字サイズ16px以上・本文コントラストはWCAG AA基準（コントラストチェッカーで主要画面を確認）・タップ対象44×44px以上を確保する

## 5. 技術要素サマリー

- 画面（UI）: あり
  - トップ / 地図検索・一覧

## 10. 成功指標とE2E検証手順

成功指標:
1. 桐生市周辺の実データで公開地図が5件以上作成され、任意の2枚以上の重ね合わせ表示・保存・共有が機能する
2. 外部サイト（登録ドメイン）1件以上でembed表示が稼働する
3. インフラ月額コストが目標（$0〜10）内に収まっている

### 前提条件（検証環境の準備）

- 受信確認が可能なテスト用メールアドレス1件
- 管理者アカウント1件（環境構築時にシードデータとして投入。投入手順は 03_tasks.md のタスクで定義）
- テスト用CSVファイル（列: 名称,緯度,経度,説明 の3行データ）と、位置情報列を欠いた不正CSVファイル
- embed検証用: 許可ドメインとして登録する検証用ページ（任意の静的ホスティングで可）と、未登録ドメイン上の検証用ページ
- 留意: embedのドメイン制限検証は**本サービス側のembed制御**（CSP frame-ancestors等）の確認である。Geolonia APIキーの開発ドメイン無制限許可（localhost等）と混同しないこと。ブラウザ表示の代わりに `curl -I <embed URL>` でレスポンスヘッダーの許可ドメイン設定を確認する方法でも代替可

### E2E検証手順（代表シナリオ。全要件の網羅検証は 03_tasks.md の要件⇔タスク対応表と各タスクのDone条件で担保）

1. メールアドレスで会員登録し、確認メールのリンクからアカウントを有効化してログインする → マイページが表示される
2. 地図「老舗マップ」を作成し、地図クリックでスポット1件（タイトル・説明・写真）、住所検索でスポット1件（カスタムアイコン画像をアップロードして設定）を追加する → 2件のスポットが指定アイコンで表示され、地図を開き直すと2件が収まる領域が初期表示される
3. 地図を「公開」に切り替える → 検索・一覧に表示される
4. 別の地図「カフェマップ」を作成し、テスト用CSV（3行）をインポートして公開する → スポット3件が取り込まれる。続けて不正CSVをインポートする → 行番号・理由付きのエラーで中止され、スポットは増えない
5. 未ログインのブラウザ（シークレットウィンドウ）で「老舗マップ」を開き、「カフェマップ」を重ねる → 両地図のスポットが凡例付きで同一画面に表示される
6. ログイン状態で同じ重ね合わせを「老舗×カフェ」として保存・公開し、発行URLを未ログインのブラウザで開く → 重ね合わせ状態が再現され、元地図2件のタイトル・作成者名が出典表示される
7. 「老舗マップ」のスポット1件のタイトルを変更する → 「老舗×カフェ」を再読込すると変更が反映されている（参照型の確認）
8. 「老舗×カフェ」に検証用ドメインを埋め込み許可登録し、当該ドメインのページにiframeを設置する → 地図が表示される（閲覧専用・帰属表記あり）。未登録ドメインのページでは表示されない（前提条件の留意事項参照）
9. 未ログインのブラウザから「カフェマップ」を通報し、管理者アカウントで管理者画面から非公開化する → 検索・一覧・重ね合わせ・embedから消え、「老舗×カフェ」にはレイヤー利用不可の旨が表示される
10. 「カフェマップ」をオーナーで削除する → マイページから消え、「老舗×カフェ」でもレイヤー除外が維持される
